# 08. テスト計画

## 1. テストの種類

| 種類 | ツール | 対象 | 実行タイミング |
|---|---|---|---|
| 単体テスト | Vitest | `lib/parser`, `lib/matcher`, `lib/reply`, `server/*` | 保存時・コミット前・CI |
| 結合テスト | Vitest + MSW | `/api/*` ルート（Google API はモック） | CI |
| E2E テスト | Playwright | 画面操作の一連の流れ（iPhone 15 / Pixel 7 相当のビューポート） | CI・Phase 終了時 |

## 2. 単体テスト観点

### 2.1 照合ロジック（matcher）

| 区分 | テストケース例 |
|---|---|
| 基本 | 予定なし → 参加可能 / 完全に重なる → 不可 |
| 境界（半開区間） | 前の予定が 19:00 終了・余裕 0 → 19:00 開始可 / 余裕 15 → 不可 |
| 余裕時間 | 0/15/30/60 それぞれで境界が正しく動く |
| 所要時間 | 30〜180 分それぞれ。終了が 23:00 ちょうどは可、23:15 は代替不可 |
| 統合 | 重なる区間・接する区間・包含される区間のマージ |
| 代替の優先順 | +15 と −15 が両方可 → +15 が先 / 最大 3 件で打ち切り |
| 探索範囲 | ±180 分ちょうどは対象、±195 分は対象外 |
| 提案可能時間 | 08:45 開始は代替に出ない、09:00 は出る |
| 日付またぎ | 22:00 開始 + 180 分 → 判定対象外 |
| 終日予定 | 「予定あり」の終日予定 → その日の全候補不可・代替なし / 複数日終日 |
| 取得失敗 | `errors` あり・形式不正・ネットワーク失敗 → `fetch_failed`（**available にならない**） |
| 過去 | 基準時刻より前の候補 → 対象外 |
| プロパティテスト | ランダムな busy と候補で「提案した枠は必ず busy と重ならない」「必ず範囲内」を数千回検証（fast-check、任意） |

### 2.2 日時抽出（parser）

- テストコーパス（架空の LINE 文 150 件以上）を表形式（JSON）で管理: `{ text, referenceDate, expected: [...], ambiguous: [...] }`
- 観点: 01-prd.md「11. 抽出対象表現」の全行、全角/半角、年またぎ（12 月に「1/5」）、月末（10/31 基準で「来週」）、うるう年（2/29）、曜日矛盾、列挙、箇条書き、ノイズ（URL・電話番号・金額「1,900円」・「3人」を誤抽出しない）
- 決定性: 同じ入力・基準日で 100 回実行して結果が同一
- 性能: 2,000 文字の病的入力で 50ms 以内

### 2.3 返信文（reply）

- パターン（全可・一部可・代替あり・全不可）× トーン（カジュアル・丁寧）のスナップショット
- 同月の日付省略、曜日表記、候補が 1 件 / 複数件の言い回し

### 2.4 サーバー（server）

| 対象 | テスト |
|---|---|
| session | 暗号化→復号の往復、改ざん検知、期限切れ拒否、旧鍵での復号 |
| oauth | state 不一致/欠落/再利用で拒否、PKCE パラメータ生成、スコープ不足の検知 |
| freebusy | 入力検証（件数・期間・形式）、Google 401/403/429/500/タイムアウト時のエラーコード、`errors` 付き応答で失敗扱い |
| csrf | Origin 不一致・独自ヘッダーなしで 403 |
| rate-limit | 上限超過で 429 |
| logger | 禁止キー（token, text, busy 等）が出力されない |
| env | 必須変数不足・本番で mock モードなら起動失敗 |

## 3. E2E シナリオ（Playwright・モバイル）

| # | シナリオ | 期待結果 |
|---|---|---|
| E01 | 貼り付け → 抽出 → 確認 → 照合（ダミー: 全て空き）→ コピー | 4 タップ以内でコピー完了トースト |
| E02 | 一部予定あり | 代替チップ表示、選択が返信文に反映 |
| E03 | 曖昧候補（「7時」） | 照合ボタン無効 → 午後を選択 → 有効 |
| E04 | 日時なしの文章 | 案内表示 → 手動追加で続行可能 |
| E05 | 所要時間・余裕時間の変更 | 結果が即時に再判定される（再取得なし） |
| E06 | 未連携で照合 → 連携シート → （モック OAuth）→ 戻って候補が復元される | 復元後 sessionStorage が空 |
| E07 | FreeBusy 失敗 | 「取得できませんでした」表示、「参加可能」が 1 つも表示されない |
| E08 | 認証期限切れ（401） | 再連携導線、候補保持 |
| E09 | 連携解除 | revoke 呼び出し、Cookie 削除、未連携表示 |
| E10 | XSS 文字列を貼り付け | スクリプト非実行、文字列として表示 |
| E11 | 2,001 文字の入力 | 入力制限と案内 |
| E12 | セキュリティヘッダー | CSP・HSTS・X-Frame-Options・Cookie 属性が正しい |

## 4. 品質基準（Phase 5 の合格条件）

- 全テスト成功、`lib/` カバレッジ 90% 以上、`server/` 85% 以上
- 日時抽出コーパス正解率 95% 以上
- 「空き」誤判定のテスト失敗 0 件
- axe で重大な違反 0 件
- `npm audit` で high 以上 0 件
- 実機（iPhone / Android 各 1 台以上）で E01〜E09 を手動確認

## 5. テストデータの扱い

- 実在の LINE 会話・実在の人名・実際のカレンダーデータはテストに使わない（すべて架空）。
- 実 Google アカウントでの確認は Phase 3 以降、開発者本人のテスト用アカウントのみで行う。
