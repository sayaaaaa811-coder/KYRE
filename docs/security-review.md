## 5. 残存リスクと推奨

| 項目 | 内容 | 推奨時期 |
|---|---|---|
| レート制限の精度 | サーバーのメモリで数えるため、サーバーレス環境では台数分だけ緩くなる。接続元 IP はホスティングが付ける `X-Forwarded-For` を信頼（Vercel では上書きされるため問題なし。他のホスティングでは要確認） | 利用者が増えたら外部ストア（例: Upstash Redis。**要承認**） |
| HSTS | `next.config.ts` の headers はビルド時に評価されるため、本番では `APP_ORIGIN` をビルド前に設定する（デプロイ手順書に記載） | デプロイ時 |
| 開発用ツールの脆弱性 | ESLint の Next.js 設定が依存する `braces` に high 指摘 5 件。開発時のみ使用し、公開アプリには含まれない | Dependabot の更新で解消次第 |
| GitHub Actions | 外部アクションをバージョンタグで指定（`@v4`）。より厳密にはコミット SHA での固定を推奨 | 本番公開前 |
| GitHub の設定 | Secret scanning・Push protection・Dependabot alerts を有効化（リポジトリの Settings → Code security） | **今すぐ推奨（あなたの操作）** |
| 実機確認 | iPhone の Safari での動作（自動テストは Chromium） | 限定公開前（docs/setup/device-test.md） |
| 専門家による確認 | プライバシーポリシー・利用規約 | 一般公開前 |
