# Phase 3 完了報告：Google OAuth と Calendar API

- 完了日: 2026-10-13
- ブランチ: `claude/kyre-schedule-dev-nfmsj6`

## 1. 実装内容

### 連携の流れ
1. 「空き状況を確認する」を押すと、未連携なら **連携の案内シート** が開く（取得する情報・しない情報を明記。デモも選べる）
2. 「Googleで連携する」→ Google の同意画面 → 許可
3. KYRE に戻ると **候補が自動で復元され、そのまま照合結果を表示**（入力し直し不要）
4. 2 回目以降（約 1 時間以内）はシートなしで照合
5. 右上メニュー（≡）→「設定」で連携状態の確認と **連携解除**（Google 側のトークンも失効）

### サーバー（`src/server/`、`src/app/api/`）

| API | 役割 |
|---|---|
| `GET /api/auth/google/start` | state・PKCE を生成し、暗号化した一時 Cookie（10 分）に保存して Google へ |
| `GET /api/auth/google/callback` | state を定数時間比較で検証 → サーバー側でトークン交換 → 権限（スコープ）を確認 → 暗号化セッション Cookie を設定 |
| `POST /api/freebusy` | 時間範囲だけを受け取り、Google FreeBusy を呼んで busy の時刻だけを返す |
| `POST /api/auth/disconnect` | Google でトークンを失効させ、Cookie を削除 |
| `GET /api/session` | 連携しているかどうかだけを返す |

### セキュリティ対策（docs/07-security-risks.md との対応）

| 対策 | 実装 | リスク |
|---|---|---|
| 最小権限 | `calendar.freebusy` のみ。メール等も取得しない。部分同意で権限が外れていたらトークンを即失効 | S05 |
| state・PKCE（S256） | 32 バイト乱数、1 回限り、10 分で失効 | S01, S02 |
| トークンをブラウザに出さない | AES-256-GCM で暗号化した HttpOnly・SameSite=Lax Cookie（本番は Secure・`__Host-`）。約 1 時間で失効、リフレッシュトークンは取得しない | S03, S14 |
| CSRF | POST は Origin 一致＋独自ヘッダー＋JSON 必須 | S06 |
| CSP | ページごとの nonce による厳格な CSP、`frame-ancestors 'none'` など | S07, S08 |
| 入力検証 | 範囲は最大 10 件・各 1 日以内・過去 2 日〜400 日先。本文 4KB まで。余計な項目は拒否 | S09, S10 |
| レート制限 | 空き状況: セッションあたり 30 回/10 分、IP あたり 60 回/10 分。認証: IP あたり 30 回/10 分 | S10 |
| 「空き」の誤表示防止 | Google の応答を厳密に検証。エラー・形式不正・一部失敗は全体を失敗扱い | S11 |
| ログ | 許可リスト方式（本文・トークン・予定は出力不可）。不正な値は `[redacted]` | S12 |
| オープンリダイレクト | 戻り先は `/` 固定 | S15 |
| 一時保存 | OAuth 往復中だけ候補（日時のみ）を sessionStorage に保存し、復元後すぐ削除。30 分で無効、内容を検証 | S16 |
| アカウント取り違え | 同意画面でアカウント選択を表示（`prompt=select_account`） | S18 |
| 設定ミス | 環境変数を検証。本番は https 必須、テスト用の偽 Google 指定は localhost のみ | S21 |
| 秘密情報 | 環境変数で管理、`server-only` でブラウザ側からの読み込みをビルドエラーに。ビルド成果物に秘密が含まれないことを確認 | S04 |

## 3. 動作確認方法（あなたの作業が必要です）

**本物の Google との接続は、あなたの Google アカウントでの設定が必要なため、まだ確認できていません。**
次の手順書に沿って設定し、実際に連携できるか確認してください（15〜20 分、費用なし）:

👉 [docs/setup/google-cloud.md](../setup/google-cloud.md)

確認していただきたいこと:
1. 連携後、自分のカレンダーで予定がある日時が「予定があります」になる
2. 予定がない日時が「参加できます」になる
3. 終日予定（「予定あり」に設定したもの）の日が「予定があります」になる
4. 設定画面から連携を解除できる

> 「このアプリは Google で確認されていません」という警告は、テスト中のため正常です（手順書 9. 参照）。

## 4. 残課題

| 項目 | 対応 |
|---|---|
| 本物の Google での動作確認 | 上記の手順であなたに確認していただく |
| 複数カレンダー（共有カレンダー等） | MVP ではメインカレンダーのみ（最小権限のため）。必要なら追加スコープを検討 |
| レート制限の精度 | サーバーのメモリで計数（本格公開時に外部ストアを検討。要承認） |
| ページの表示方式 | CSP の nonce のためページを毎回サーバーで生成（Next.js の静的キャッシュ機能 `cacheComponents` は無効化）。小規模なら性能上の問題はありません |
| プライバシーポリシー・利用規約 | 草案。Phase 5 で確定（公開前に専門家確認を推奨） |
| 開発用ツールの `npm audit` 指摘 | 開発専用の部品のみ（公開アプリに含まれない）。継続監視 |
| 次の Phase | Phase 4：返信文生成 |
