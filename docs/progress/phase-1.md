## 1. 実装内容

### Phase 0（準備）
- Next.js 16.4 / React 19 / TypeScript（strict）/ Tailwind CSS 4 のプロジェクト作成
- Vitest（単体テスト）、Playwright（E2E）、ESLint、Prettier の設定
- ESLint で `console` の直接使用と `dangerouslySetInnerHTML` を禁止（ログ漏洩・XSS 対策）
- GitHub Actions（CI）: push のたびに lint・型チェック・単体テスト・E2E を自動実行
- デザイントークン（白基調・控えめなゴールド）、Noto Sans JP / Noto Serif JP（ビルド時に取得して自己ホスト）

### Phase 1（UI と照合ロジック）
| 対象 | ファイル | 内容 |
|---|---|---|
| 照合ロジック | `src/lib/matcher/` | 余裕時間で busy を拡張→統合→半開区間で判定→前後 3 時間・15 分刻み・近い順（同距離は後ろ優先）・09:00〜23:00・最大 3 件で代替探索 |
| 安全側の判定 | 同上 | 取得失敗・取得範囲外の日・不正なデータのときは決して「参加可能」にしない。過去・日付またぎは「判定対象外」 |
| 日時ユーティリティ | `src/lib/time/` | Asia/Tokyo を明示した計算（サーバーや端末のタイムゾーンに左右されない） |
| ダミーカレンダー | `src/lib/calendar/mock.ts` | 5 種類のシナリオ。Phase 3 で同じ形の Google 実装に差し替える |
| 画面 ① 入力 | `MessageInputStep` | 貼り付け、クリップボード読み取り、2,000 文字制限、基準日の変更 |
| 画面 ② 確認 | `CandidateReviewStep` | 候補の追加・編集・削除（最大 10 件）、要確認の解消、所要時間・余裕時間 |
| 画面 ③ 結果 | `ResultStep` | 候補ごとのステータス、代替案、設定変更で即時再判定、取得失敗時の再試行 |
| 画面遷移 | `useStepHistory` | 端末の「戻る」でステップを戻れる |

## 3. 動作確認方法

1. README の「自分のパソコンで動かす手順」に従って `npm install` → `npm run dev`
2. <http://localhost:3000> を開く（スマホ表示はブラウザの開発者ツールで端末サイズを選ぶと確認しやすいです）
3. 適当な文章を貼り付け →「候補を抽出する」（Phase 1 では自動抽出は未実装のため、案内が出ます）
4. 「＋ 候補を追加」で日時を入力（例: 偶数日の 19:00 → 予定あり＋代替案、奇数日の 19:00 → 参加可能）
5. 「空き状況を確認する」→ 結果画面で「変更」から所要時間・余裕時間を変えると即座に結果が変わります
6. URL に `?mock=error` を付けると取得失敗時の表示を確認できます
