## 0. 追加のご要望への対応（Phase 2 の前に実施）

**「活動時間を 9:00〜23:00 に固定せず、毎回ユーザーが選べるように」**

- 代替案を探す時間帯を、候補確認画面と結果画面で毎回選べるようにしました（1 時間単位、0:00〜24:00）。
- 初期値は **24 時間（いつでも OK）**。よく使う「24時間 / 9〜18時 / 18〜24時」はワンタップで選べます。
- 選んだ時間帯は保存しません（毎回初期値の 24 時間から始まります）。
- 日付をまたぐ候補は、これまでどおり判定対象外です（例: 23:00 開始・90 分）。
- PRD（docs/01-prd.md）を v0.2 として更新しました。

| 対象 | ファイル | 内容 |

### 「要確認」になるケース（照合前に必ずユーザーが確認）

| 種類 | 例 | 表示 |
|---|---|---|
| 午前・午後が不明 | 「7時」（1〜8時で手がかりなし） | 午後と仮定し、午前／午後を選択 |
| 時間帯のみ | 「明日の夜」 | 夜 19:00 / 昼 12:00 などを仮置き |
| 時刻なし | 「金曜空いてる？」 | 12:00 を仮置きし、入力を促す |
| 時刻の引き継ぎ | 「10/21も同じ時間で」 | 他の候補と同じ時刻にした旨を表示 |
| 日付なし | 「7時集合で」 | 基準日を仮置き |
| 月の推定 | 基準日 10/13 に「5日」 | 11/5 と解釈した旨を表示 |
| 曜日の矛盾 | 「10/20(水)」（実際は火曜） | 日付どおり／曜日どおりを選択 |
| 来週・再来週 | 「来週の火曜」 | 月曜始まりで解釈（ご承認の D6 どおり）。解釈が分かれる日曜基準のときは両方を選択肢に |
| 今日と同じ曜日 | 火曜日に「火曜」 | 今日／来週を選択 |
| 過去・3 か月以上先 | 「10/12」「2/10」 | 注意を表示 |

### 誤抽出の防止
金額（1,900円）、人数（3人）、電話番号、URL、「2時間」「3日間」「1日中」「10分」などは日時として扱いません。

### 個人情報
解析はすべて端末（ブラウザ）内で行い、メッセージ本文はサーバーにも外部 AI にも送信しません。AI は使っていないため費用は発生しません。

## 3. 動作確認方法

1. `npm run dev` で起動し、<http://localhost:3000> を開く
2. 次のような文章を貼り付けて「候補を抽出する」を押してみてください
   - `来週どこか飲みに行こう！ 10/20(火)か21(水)の19時〜どう？` → 2 件がそのまま抽出
   - `20日の7時に集合で！` → 「午前・午後どちらですか？」と表示され、選ぶまで照合できない
   - `10/20(水) 19時` → 曜日の矛盾を指摘
   - `10/20 19:00-21:00` → 所要時間が 120 分に自動設定
   - `明日の夜あいてる？` → 19:00 を仮置きし確認を求める
3. 「基準日」を変えると「明日」「来週」の解釈が変わります（数日前に届いたメッセージ用）

## 4. 残課題

| 項目 | 内容 |
|---|---|
| 漢数字 | 「七時」「二十日」は未対応（手入力で修正可能）。必要なら追加します |
| 否定表現 | 「20日は無理、21日なら」の「20日」も候補になります（削除ボタンで除外）。文脈理解は AI 解析の領域のため MVP では対象外 |
| 「来週」の要確認 | ご承認どおり常に要確認にしています。タップが増えるため、解釈が分かれる場合（日曜基準など）だけ要確認にする方式にも変更できます |
| 日付の範囲 | 「11/21〜22」は両日を候補にします（旅行の初日だけ必要な場合は削除） |
