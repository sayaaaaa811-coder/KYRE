# 01. PRD（製品要求仕様書） — KYRE Schedule MVP

- 版: v0.1（承認待ち）
- 作成日: 2026-10-13
- 対象: KYRE 第1号プロダクト「KYRE Schedule」

---

## 1. 製品概要

LINE などで届いた日程候補の文章を貼り付けるだけで、候補日時を抽出し、ユーザーの Google カレンダーの空き状況と照合して「参加できる日時」と「前後の代替案」を提示し、そのまま送れる返信文まで作る無料 Web アプリ。

### 1.1 解決する課題

| 現状の手間 | KYRE Schedule での解決 |
|---|---|
| LINE とカレンダーアプリを何度も行き来する | 貼り付け1回で全候補をまとめて照合 |
| 「19時〜」の候補に対し、前の予定の終了時刻や移動時間を頭で計算する | 所要時間・前後の余裕時間を考慮して自動判定 |
| 全候補 NG のとき、代わりの時間を自分で探す | 前後3時間以内で代替枠を最大3件提案 |
| 返信文を考えるのが面倒 | 自然な日本語の返信文を自動生成しコピー |

### 1.2 ターゲット

- 日本の一般ユーザー（20〜40代中心、スマートフォン利用が主）
- 用途: 友人との食事・遊び・旅行、ちょっとした打ち合わせ
- Google カレンダーで予定を管理している人

### 1.3 成功指標（MVP 限定公開期間）

| 指標 | 目標 |
|---|---|
| 貼り付けから返信文コピーまでの完了率 | 60% 以上 |
| 貼り付けからコピーまでの中央所要時間 | 60 秒以内 |
| 日時抽出の正解率（テストコーパス） | 95% 以上（曖昧ケースは「確認必要」と正しく判定できれば正解） |
| 「空き」の誤判定（実際は予定あり） | 0 件（最重要品質指標） |

※ 指標の計測は、本文や予定を一切送らない匿名イベントのみで行う（詳細は承認後に設計。MVP 初期は計測なしでも可）。

### 1.4 スコープ外（MVP では実装しない）

- 日付をまたぐ候補（例: 23:00〜翌1:00）の判定
- Google 以外のカレンダー（iCloud, Outlook）
- カレンダーへの予定の書き込み
- 複数カレンダー（共有カレンダー等）の照合 ※「6. 制約」参照
- アカウント登録・データベース・履歴保存
- AI（LLM）による日時解析 ※「7. AI 解析の方針」参照
- 移動時間の自動計算（場所を考慮した判定）

## 2. ユーザーストーリー

1. 友人から「来週どこか飲みに行こう！ 10/20(火)か21(水)の19時〜どう？」と LINE が来た。
2. メッセージを長押し→コピーし、KYRE Schedule を開いて貼り付ける。
3. 「10/20(火) 19:00」「10/21(水) 19:00」が抽出され、内容を確認する。
4. 「空き状況を確認」を押す（初回のみ Google 連携）。
5. 「20日 ◎参加可能」「21日 × 予定あり → 代替案 20:30 / 17:30」と表示される。
6. 返信文「誘ってくれてありがとう！ 10/20(火) 19:00〜なら行けるよ。21(水)は 20:30〜なら大丈夫！」を確認してコピー。
7. LINE に戻って貼り付けて送信。

## 6. 制約・前提

- **照合対象は primary カレンダーのみ**: 最小権限の FreeBusy スコープではカレンダー一覧を取得できないため。複数カレンダー対応には `calendar.calendarlist.readonly` 等の追加スコープが必要で、MVP 後に検討。
- **「予定なし（free）」に設定された予定は busy として返らない**: Google の仕様。Google カレンダーで終日予定を作成すると既定が「予定なし」になる場合があるため、画面上で注意書きを表示する。
- **Google OAuth アプリ審査**: FreeBusy スコープは Google の分類上「センシティブスコープ」に該当する見込み（公開前に Google Cloud Console の表示で最終確認）。審査完了まではテストモード（テストユーザー最大100人）で限定公開する。
- **データベースなし**: セッションは暗号化 Cookie で管理する（詳細は 03-architecture.md）。

## 7. AI 解析の方針

MVP では **AI 解析を使わない**。ルールベースで抽出できない場合は「日時を見つけられませんでした。手動で追加してください」と案内し、手入力に誘導する。

将来 AI 解析を追加する場合の検討事項（追加時は改めて承認をいただきます）:

| 観点 | 内容 |
|---|---|
| API コスト | 1 回あたり入力 約500〜1,500 トークン程度。小型モデル利用で 1 回あたり 0.1〜0.5 円程度の見込み（モデル・料金は導入時点で再確認）。無料アプリのため、ルールベース失敗時のみ呼び出す・1日の上限回数を設ける。 |
| 個人情報送信 | LINE メッセージには人名・場所・個人的内容が含まれるため、外部 AI 事業者へ送信することになる。事前に明示の同意（オプトイン）を取る・データを学習に使わない契約／設定の API を選ぶ・プライバシーポリシーに記載する。 |
| エラー処理 | タイムアウト（5秒）・失敗時はルールベース結果＋手動入力にフォールバック。AI の出力は必ず JSON スキーマ検証し、AI 由来の候補は全件「要確認」扱いにする。 |

## 8. 日時判定ルール（照合ロジック仕様）

### 8.1 定数（初期値）

| 項目 | 値 |
|---|---|
| タイムゾーン | Asia/Tokyo |
| 所要時間 | 90 分（30/60/90/120/180） |
| 前後余裕時間 | 15 分（0/15/30/60） |
| 代替枠探索範囲 | 元の開始時刻 ±3 時間（開始時刻ベース） |
| 提案可能時間 | 09:00〜23:00（枠の開始 ≥ 09:00 かつ 終了 ≤ 23:00） |
| 代替案件数 | 最大 3 件 |
| 探索刻み | 15 分 |

### 8.2 アルゴリズム

1. **busy 区間の作成**: FreeBusy の各 busy 区間 `[s, e)` を余裕時間 `b` だけ広げ `[s − b, e + b)` とする。
2. **統合**: 開始時刻でソートし、重なる・接する区間をマージして「統合 busy 区間」を作る。
3. **候補判定**: 候補枠 `[t, t + d)`（d = 所要時間）が統合 busy 区間のどれとも重ならなければ「参加可能」。
   - 境界は半開区間。予定が 19:00 に終わり余裕 0 分なら、19:00 開始は可能。
4. **代替探索**（候補が不可の場合のみ）:
   - オフセット `±15, ±30, …, ±180` 分を、**|オフセット| の小さい順、同距離なら＋（後ろ）を先**に並べる。
   - 例: +15, −15, +30, −30, …, +180, −180
   - 各 `t' = t + オフセット` について、(a) `t' ≥ 09:00` (b) `t' + d ≤ 23:00` (c) 同じ日付内 (d) 統合 busy と重ならない — をすべて満たすものを採用。
   - 先頭から最大 3 件で打ち切り。
5. **日付またぎ**: 元の候補で `t + d` が翌日 0:00 を超える場合は「日付をまたぐため判定対象外」と表示（所要時間を短くする案内つき）。
6. **元の候補が 09:00〜23:00 の外**: 元の候補自体は判定する（ユーザーが提示された日時のため）。代替は 09:00〜23:00 内のみ。
7. **終日予定**: FreeBusy は「予定あり」に設定された終日予定を、カレンダーのタイムゾーンでの 0:00〜翌0:00 の busy 区間として返す。区間はすべて絶対時刻（UTC）で扱うため、特別扱いせず正しくブロックされる。複数日の終日予定も同様。
8. **取得失敗**: API エラー、レスポンスの `calendars[id].errors` が存在する、レスポンス形式不正のいずれかの場合、該当候補は「取得失敗」とし、**絶対に「参加可能」と表示しない**。
9. **過去の日時**: 「過去の日時です」と表示し判定しない。

### 8.3 判定ステータス

| ステータス | 表示 | 色 |
|---|---|---|
| available | ◎ 参加可能 | ゴールド系アクセント |
| busy_with_alternatives | × 予定あり（代替案 n 件） | グレー＋代替チップ |
| busy_no_alternatives | × 予定あり（前後3時間に空きなし） | グレー |
| out_of_scope | − 判定対象外（日付またぎ／過去） | 薄グレー |
| fetch_failed | ! 取得できませんでした | 警告色（赤系は控えめ） |

### 8.4 決定が必要な点（承認時にご確認ください）

- 代替案同士が近い時刻（例: 19:15, 18:45, 19:30）になる場合もそのまま 3 件出す想定。「30分以上離す」等の間引きは MVP では行わない。

## 9. 返信文生成ルール（F09）

テンプレート＋条件分岐で生成（AI 不使用、端末内処理）。

| パターン | カジュアル例 | 丁寧例 |
|---|---|---|
| 1件以上参加可能 | 誘ってくれてありがとう！10/20(火) 19:00〜なら行けるよ！ | お誘いありがとうございます。10月20日(火) 19:00〜でしたら参加可能です。 |
| 一部不可・代替あり | 21(水)は19時だと難しいけど、20:30〜なら大丈夫！ | 21日(水)は19:00からは難しいのですが、20:30以降でしたら調整可能です。 |
| 全て不可・代替なし | ごめん、その日程だと全部難しそう…別の日でもいい？ | 申し訳ありません、ご提示の日程はいずれも都合がつかず…別日程をご相談できますでしょうか。 |

- 参加可能が複数ある場合は全部列挙するか「どれでもOK」とまとめる。
- 生成文はテキストエリアで自由に編集してからコピーできる。

## 11. 抽出対象表現（Phase 2 の仕様）

| 種類 | 例 | 解釈 |
|---|---|---|
| 月日 | 10/20, 10月20日, １０／２０（全角） | 基準日以降で最も近いその月日（年をまたぐ場合は翌年） |
| 日のみ | 20日, 20(火) | 基準月の 20 日。過去なら翌月 → **要確認** |
| 曜日付き | 10/20(火), 10/20（火曜） | 日付と曜日が矛盾したら **要確認** |
| 相対日 | 今日, 明日, 明後日, あさって | 基準日から計算 |
| 相対週 | 今週金曜, 来週の火曜, 再来週 | 週の始まりは月曜。**「来週」の解釈は文化差があるため要確認バッジ付き** |
| 週末 | 今週末, 来週末, 土日 | 土・日の 2 候補に展開（時刻なしなら要確認） |
| 時刻 | 19時, 19:00, 19時半, 7時半, 午後7時, PM7 | 24時間表記に正規化 |
| 時刻範囲 | 19〜21時, 19:00-21:00, 19時から | 開始・終了 |
| 時刻の曖昧 | 7時（午前／午後なし、1〜8時） | 午後と仮定し **要確認** |
| 時間帯 | 朝, 昼, ランチ, 夕方, 夜, ディナー | 朝 9:00 / 昼・ランチ 12:00 / 夕方 17:00 / 夜・ディナー 19:00 を仮置きし **要確認** |
| 列挙 | 20か21, 20・21・23日, 20日と21日の19時 | 日付ごとに候補を展開し、時刻を共有 |
| 箇条書き | 「・10/20 19時」「①…」 改行区切り | 行ごとに抽出 |
| 対象外 | 「先週の〜」「去年」等の過去表現、時刻のみで日付なし | 日付なしは **要確認**（日付入力を促す） |

- 抽出結果は最大 10 候補。基準日から 90 日より先は要確認。

## 12. エラー一覧（F11）

| 状況 | 表示文言（例） | 次の行動 |
|---|---|---|
| 日時が見つからない | 日時を見つけられませんでした。候補を手動で追加してください。 | ＋候補を追加 |
| 曖昧な日時 | 「7時」は午前・午後どちらですか？ | 選択して確定 |
| Google 未連携 | 空き状況の確認には Google カレンダーとの連携が必要です。 | Google で連携 ／ デモで試す |
| 権限が付与されなかった | カレンダーの空き状況へのアクセスが許可されませんでした。 | 再度連携（権限チェックボックスの案内図つき） |
| 認証期限切れ | 連携の有効期限が切れました。もう一度連携してください。 | 再連携（候補は保持） |
| API 失敗・タイムアウト | 予定を取得できませんでした。空き状況は表示していません。 | 再試行 |
| レート制限 | 短時間に操作が集中しました。少し時間をおいてお試しください。 | 待機 |
| オフライン | インターネットに接続されていません。 | 再試行 |
| コピー失敗 | コピーできませんでした。文章を長押ししてコピーしてください。 | 手動コピー |
