# 限定公開（デプロイ）手順書

> ⚠️ **この手順は、あなたの明示的な承認をいただいてから実施します。**
> 外部サービスへのデプロイ、有料プラン・独自ドメインの契約が含まれる可能性があるためです。
> まだ何も実施していません。

## 0. 事前に決めていただくこと

| # | 決めること | 選択肢 | 補足 |
|---|---|---|---|
| A | 運営者名・お問い合わせ先 | 個人名／屋号／会社名と、問い合わせ用メールアドレス | プライバシーポリシー・利用規約・Google の同意画面に表示されます。個人のメールアドレスを出したくない場合は、専用のアドレスを作ることをおすすめします |
| B | ホスティング | ① Vercel Hobby（無料） ② Vercel Pro（有料） ③ その他（Cloudflare、Google Cloud Run など） | **Vercel の無料プランは非商用利用に限られます**。KYRE を事業として運営する場合は有料プランが必要になる可能性があります（料金は契約前に Vercel の公式サイトで最新情報をご確認ください） |
| C | ドメイン（URL） | ① `kyre-schedule.vercel.app` のような無料の URL ② 独自ドメイン（例: `schedule.kyre.jp`、年額 1,000〜数千円程度） | Google の審査（一般公開）では、所有を証明できる独自ドメインが事実上必要です。限定公開は ① で始め、一般公開前に ② に移ることもできます |
| D | 限定公開の対象者 | テストユーザーとして登録する Gmail アドレス（最大 100 人） | Google Cloud の「対象」→「テストユーザー」に登録した人だけが連携できます |

## 1. Vercel にプロジェクトを作る（承認後）

1. <https://vercel.com/> で「Sign Up」→「Continue with GitHub」で登録します（B で無料プランの場合はクレジットカード不要）。
2. 「Add New…」→「Project」→ `sayaaaaa811-coder/KYRE` を選んで「Import」します。
3. Framework Preset が「Next.js」になっていることを確認します。
4. **まだ「Deploy」は押さず**、次の環境変数を「Environment Variables」に入力します。

| 名前 | 値 |
|---|---|
| `GOOGLE_CLIENT_ID` | 本番用のクライアント ID（2. で作成） |
| `GOOGLE_CLIENT_SECRET` | 本番用のクライアント シークレット |
| `GOOGLE_REDIRECT_URI` | `https://（公開 URL）/api/auth/google/callback` |
| `SESSION_SECRET` | **ローカルとは別の値を新しく生成**（`node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`） |
| `APP_ORIGIN` | `https://（公開 URL）`（末尾の `/` なし） |

- `GOOGLE_ENDPOINT_OVERRIDE` は **絶対に設定しないでください**（テスト専用。本番では設定してもアプリが拒否します）。
- 環境変数はビルド時にも使われるため（HSTS の設定）、**最初のデプロイの前に** 入力してください。

## 2. Google Cloud に本番用のクライアントを作る

1. docs/setup/google-cloud.md の手順 7 と同じ要領で、新しいクライアント `KYRE Schedule (production)` を作ります。
2. 承認済みのリダイレクト URI に `https://（公開 URL）/api/auth/google/callback` を登録します。
3. 「ブランディング」で、アプリのホームページ・プライバシーポリシー（`https://（公開 URL）/privacy`）・利用規約（`/terms`）の URL を登録します。
4. 「対象」で、公開ステータスは **テスト中のまま**、限定公開の参加者をテストユーザーに追加します。

> 独自ドメインを使わない場合、Google の画面で「承認済みドメイン」として `vercel.app` を登録できないことがあります。その場合は表示されたエラーをお知らせください。独自ドメインへの切り替えを含めてご相談します。

## 3. デプロイと確認

1. Vercel で「Deploy」を押します。
2. 表示された URL を開き、次を確認します。
   - デモ（ダミーカレンダー）で一通り動く
   - Google 連携ができ、自分のカレンダーの予定が反映される
   - docs/setup/device-test.md の実機確認
3. 問題がなければ、テストユーザーに URL を共有します。案内文の例:

```
KYRE Schedule（試用版）のご案内
LINE で届いた日程候補を貼り付けると、Google カレンダーの空き状況を見て、参加できる日時と返信文を作ります。
URL: https://（公開 URL）
・Google 連携時に「このアプリは確認されていません」と出ますが、試用版のためです（詳細 → 移動）
・取得するのは予定がある時間帯だけで、予定の内容やメッセージは保存しません
感想・不具合はこちらへ: （連絡先）
```

## 4. 公開後の運用

| 作業 | 頻度 |
|---|---|
| Dependabot の更新提案（プルリクエスト）の確認 | 週 1 回 |
| Vercel のログで `freebusy_failed` などのエラーが増えていないか確認 | 週 1 回 |
| シークレット・`SESSION_SECRET` の定期的な入れ替え | 年 1 回程度（`SESSION_SECRET_PREVIOUS` を使えば連携中の利用者を切らずに入れ替え可能） |
| テストユーザーの追加・削除 | 随時 |

docs/setup/oauth-verification.md を参照してください（独自ドメイン・審査申請が必要です。**要承認**）。
