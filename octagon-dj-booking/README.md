# オクタゴン 平日サブフロア 学生DJブッキング管理（Googleスプレッドシート）

学生DJの紹介・打診・出演確定を複数の担当者で管理し、出演日ごとの「集客コミット人数」と「実来場人数（学生DJ経由）」を把握するためのスプレッドシートです。Google Apps Script（`Code.gs`）でタブ・見出し・入力規則・書式を自動で作ります。

## セットアップ手順

1. Googleスプレッドシートを新規作成します（既存のスプレッドシートでも使えます）。
2. メニューの **拡張機能 → Apps Script** を開きます。
3. 最初からある `コード.gs`（`Code.gs`）の中身をすべて消し、このフォルダの `Code.gs` の内容を貼り付けて保存します（💾 または Ctrl/⌘ + S）。
4. 上部の関数選択で **`setupBookingSheet`** を選び、**実行** を押します。
5. 初回は権限の承認画面が出ます。「権限を確認」→ 自分のアカウントを選び →「許可」を押します（「このアプリは確認されていません」と出たら「詳細」→「（プロジェクト名）に移動」）。
6. スプレッドシートに戻ると、次のタブができています。スプレッドシートを再読み込みすると、上部に「ブッキング管理」メニューが出ます。

| タブ | 内容 |
|---|---|
| 使い方 | 入力の流れ・ルール・色の意味・共有の注意 |
| DJ一覧 | 1行1人の名簿。DJ IDは自動発行 |
| 紹介履歴 | 1行1件の紹介（同じDJへの複数紹介も1件ずつ） |
| 出演・集客管理 | 1行1出演。コミット人数と実来場人数を記録 |
| 日別集計 | 営業日ごとの自動集計（入力不要） |

- 本番シートには、実名や架空のDJデータを入れていません。
- シートの共有範囲は変更しません。年齢・大学名・連絡先を含むため、共有は関係者だけに限定してください。
- 新規スプレッドシートに最初からある空の「シート1」は、空の場合だけ削除します。

## 再実行について

`setupBookingSheet` は何度実行しても安全です。

- 登録済みのデータ（DJ一覧・紹介履歴・出演・集客管理の2行目以降）は消しません。
- 同じ名前のタブがあれば作らず、編集時トリガーも既にあれば追加しません。
- 見出し・数式・書式・入力規則・条件付き書式・保護（警告のみ）を整え直します。自分で追加した条件付き書式は、再実行すると消えます。
- 「使い方」タブは毎回書き直します。
- データが入っているタブで列の見出しが想定と違う場合（列を入れ替えた場合など）は、データを守るため何も変更せずエラーで止まります。

## 主な仕組み

### DJ ID
- DJ一覧でDJ名またはInstagram IDを入力すると、編集時トリガーが `DJ-0001` 形式のIDを発行します（出演区分「未定」・対応状況「候補」が空欄なら初期値も入ります）。
- IDは値として書き込むので、並べ替えやDJ名の変更では変わりません。1セルだけ書き換え・削除した場合は元に戻します。
- 連番は「保存済みの最終番号（ドキュメントプロパティ）」と「シート上の最大番号」の大きい方から続けます。ロック（`LockService`）の中で発行するので、複数人の同時登録・複数行の貼り付け・行削除後でも番号が重複・再利用されません。
- 行のコピーでIDが重複した場合は赤で表示します。新しい方の行のIDセルを消すと新しいIDが発行されます。

### Instagram の重複チェック
- `@`／`＠` の有無、大文字・小文字、前後や途中の空白、プロフィールURLの貼り付けを同じIDとして正規化し（「Instagram正規化（自動）」列）、同じ値の行を赤で表示します。
- 重複行は自動で削除・統合しません。「Instagramリンク（自動）」列からプロフィールを開けます。

### DJ IDの参照（紹介履歴・出演・集客管理）
- DJ IDはDJ一覧からプルダウンで選択します。紐づけはすべてIDで行い、DJ名は自動表示です。
- スマホで選びにくい場合は、DJ名またはInstagram IDを入力すると、1人に特定できればIDに置き換わります。候補が複数ある場合はIDに置き換えず、セルのメモに候補を表示します。
- 出演登録でDJ IDを選ぶと、空欄のブッキング担当者・出演区分をDJ一覧から補完します。紹介履歴では空欄の紹介日に今日の日付を入れます。

### 人数の扱い
- 人数欄（目標・コミット・実来場）は0以上の整数のみ入力できます。空欄＝未確認、0＝確認済みの0人です。
- 出演ごとの達成率は、コミットが0・空欄、または実来場が空欄なら空欄です。
- 日別集計はキャンセルをすべて除外します。日別の達成率は「出演済で、実来場とコミットが入力済み・コミット1人以上の行」の実来場合計 ÷ コミット合計です。
- 実来場が1件も入力されていない日は実来場合計を空欄にします。同じ考え方で、コミットが1件も入力されていない日はコミット合計も空欄にします（未入力の件数は「コミット未入力枠数」に出ます）。

### 色
| 色 | 意味 |
|---|---|
| 淡いグレー | 自動計算・自動表示の列（入力しない） |
| 淡い赤 | Instagram・DJ IDの重複候補、名簿にないDJ ID |
| 淡い黄 | 確定・出演済でコミット未入力、出演済で実来場未入力 |
| 淡い紫 | 同じ営業日に同じDJの出演行が複数ある（確認用） |

## 運用上の注意

- 編集時トリガーは `setupBookingSheet` を実行した人のアカウントで動きます。その人がスプレッドシートの編集権限を失うとID発行が止まるため、そのときは別の担当者が `setupBookingSheet` を再実行してください。トリガーが2人分になっても、処理はロックの中で行い、すでに処理済みの行は変更しないので、IDが二重に発行されることはありません。
- スマホアプリでは「ブッキング管理」メニューは表示されませんが、ID発行などの自動処理はスマホからの入力でも動きます。
- 入力規則と書式は、初期設定を実行した時点のシートの行数（1000行以上）まで設定されます。行を追加した場合は `setupBookingSheet` を再実行してください。
- 自動計算の列（グレー）に値を入力すると `#REF!` になります。入力した値を消せば元に戻ります。

## 動作確認の状況

この作業環境からは Google アカウント・Googleスプレッドシートに接続できなかったため、**実際のGoogleスプレッドシート上での動作確認はしていません**。次の確認だけを行いました。

- 構文チェック（Node.js）
- Apps Script のAPIを模したモック環境で `setupBookingSheet` と編集時トリガーを実行し、次の点を確認：
  - タブ5つの作成、空の「シート1」の削除、トリガーが1件のみ
  - 複数行貼り付けでの連番発行、DJ名変更でIDが変わらないこと、ID書き換えを元に戻すこと、削除済み番号を再利用しないこと、連続した登録でIDが重複しないこと
  - 同じDJへの複数紹介（ID・Instagram ID・DJ名のどれで入力してもIDに置き換わる）、Instagramが重複するときは自動で選ばないこと
  - レギュラーDJの複数回出演の登録と、担当者・出演区分の補完
  - 再実行（2回）でデータが変わらず、タブ・トリガー・保護が増えないこと、見出しが違うときは変更せず止まること
- 日別集計と出演ごとの差・達成率の数式を、同じ条件の1行ずつの数式に変換してLibreOfficeで計算し、キャンセル除外、空欄と0の区別、日別達成率が期待値どおりになることを確認

Google Sheets 固有の機能（`ARRAYFORMULA`・`VSTACK`・`SORT/UNIQUE/FILTER`・`REGEXREPLACE`・`HYPERLINK`、プルダウン、条件付き書式、保護、トリガー、`LockService`）は未確認です。初回のセットアップ後に、下の確認項目を一度試してください。

### 初回の確認項目（テスト用の行は確認後に削除）
1. DJ一覧にDJ名を2行続けて貼り付け → DJ IDが2件発行される。
2. Instagram IDに `@Abc` と ` abc ` を入れる → 2行が赤くなる。
3. 紹介履歴で同じDJ IDを2行入力 → DJ一覧の「紹介件数」が2になる。
4. 出演・集客管理で同じDJを別の営業日に2行登録し、片方をキャンセルにする → 日別集計にキャンセルが含まれない。
5. 出演済でコミット5・実来場を空欄 → 実来場が黄色、日別の実来場合計は空欄。実来場に0を入力 → 実来場合計が0、達成率0%。
6. `setupBookingSheet` を再実行 → 入力した行が残り、タブが増えない（Apps Script の「トリガー」画面で `onBookingSheetEdit` が1件のみ）。
